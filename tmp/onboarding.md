# Developer Onboarding Checklist

## Mentor Assignment

| Item | Detail |
|------|--------|
| **Mentor** | _Assigned on Day 1_ |
| **Buddy** | _Assigned on Day 1 (peer for day-to-day questions)_ |
| **Check-in cadence** | Daily (Week 1), weekly (Month 1) |

---

## Day 1 — Setup & Introductions

### Environment Setup
- [ ] Provision laptop / access to dev environment
- [ ] Install required tools: IDE, terminal, browser dev tools
- [ ] Set up SSH keys and GPG signing
- [ ] Configure IDE with team-standard extensions/linting rules
- [ ] Verify access to: email, Slack, CI/CD dashboard

### Accounts & Access
- [ ] Grant access to version control (GitHub/GitLab)
- [ ] Grant access to project management (Jira/Linear)
- [ ] Grant access to CI/CD pipelines
- [ ] Grant access to cloud provider (staging/dev accounts)
- [ ] Grant access to logging/monitoring (Datadog, Sentry, etc.)

### Introductions
- [ ] Meet 1:1 with mentor
- [ ] Meet 1:1 with engineering manager
- [ ] Join team standup and introduce yourself
- [ ] Schedule informal 1:1s with 3–5 team members
- [ ] Add team calendar events (standup, retro, planning)

### Quick Win
- [ ] Complete "Hello World" run of the main application locally
- [ ] Ask questions freely — no question is too basic

---

## Week 1 — Repo Access & First Contributions

### Documentation
- [ ] Read the team README and architecture overview
- [ ] Review the contributing guidelines
- [ ] Read recent meeting notes or retros (last 2–3)
- [ ] Familiarize yourself with the coding standards

### Repository Setup
- [ ] Clone and run the main project locally
- [ ] Understand the project structure and module boundaries
- [ ] Run the test suite and confirm it passes
- [ ] Set up pre-commit hooks

### First PR
- [ ] Pick a good first issue (labelled `good-first-issue` or `onboarding`)
- [ ] Implement the fix/feature with mentor guidance
- [ ] Submit your first pull request
- [ ] Participate in at least one code review (as author or reviewer)

### Tooling
- [ ] Set up local debugging configuration
- [ ] Learn the team's branching strategy and PR workflow
- [ ] Understand the deployment process (staging → production)

---

## Month 1 — Independent Work

### Code Ownership
- [ ] Complete 3–5 PRs independently
- [ ] Review at least 3 PRs from teammates
- [ ] Handle at least one bug in production (with mentor oversight)

### Process Participation
- [ ] Participate actively in sprint planning
- [ ] Write and estimate stories for sprint tasks
- [ ] Attend and contribute to retrospectives
- [ ] Present a tech talk or design doc review (optional, encouraged)

### Architecture & Domain
- [ ] Map out the data flow for the team's core service
- [ ] Identify key dependencies and their owners
- [ ] Understand the CI/CD pipeline end-to-end

### Self-Assessment
- [ ] Meet with mentor to discuss progress and blockers
- [ ] Set goals for Month 2
- [ ] Identify areas for further learning or training
