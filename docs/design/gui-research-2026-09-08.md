# GUI Research — Perplexity Computer, OpenHands, Hermes Agent

Date: 2026-09-08

Scope: frontend/GUI research on three autonomous-agent products, intended as the evidence base for a follow-up implementation plan that redesigns the Tektos Ultima frontend (Next.js 15 + React 19 + Tailwind 4, `@assistant-ui/react` 0.14, Monaco, `@xterm/xterm` 6, D3 7, WebSocket-only envelope protocol).

Sourcing rules used in this report: every factual claim about a product cites a URL fetched during this research session. OpenHands and Hermes Agent claims are drawn from actual source files in their repositories (`package.json`, component files, stores, style sheets, docs), not from README marketing copy. Perplexity Computer is closed-source; its section is built from Perplexity's own product pages, help-center articles and changelogs, plus third-party hands-on reviews, and its implementation-level section is explicitly marked unavailable rather than speculated.

---

## Executive summary

- **The three products occupy three different structural archetypes.** Perplexity Computer is a *conversation-plus-artifact* product where the agent's machine is deliberately hidden ([Builder.io's hands-on review](https://www.builder.io/blog/perplexity-computer) says everything happens in a cloud sandbox "with no window in"); OpenHands' web app is a *two-pane developer control center* (chat left, tabbed workspace right) shipped as the package `@openhands/agent-canvas` ([package.json](https://github.com/OpenHands/OpenHands/blob/main/package.json)); Hermes Agent is a *chat-first desktop shell with a tiling pane tree* whose design doc states plainly that "Chat is the home surface" ([apps/desktop/DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Hermes is the closest stack analogue to Tektos and the richest single source of copyable patterns.** Its desktop app pins `@assistant-ui/react` 0.14.24 alongside nanostores, CodeMirror 6, xterm 6 with `node-pty`, Radix, cmdk, Tabler icons and Tailwind 4 ([apps/desktop/package.json](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/package.json)) — the same assistant-ui major that Tektos already depends on.
- **Both open-source products treat "agent is working" as a small, quiet, in-flow indicator, not a big panel.** OpenHands renders a single pill-shaped live-activity chip with a pulsing dot and `aria-live="polite"` ([chat-interface.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/chat-interface.tsx)); Hermes renders scaffold status rows with shimmer, an activity timer, and a one-line `ToolRunTicker` that slides rows upward ([status.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/status.tsx), [run-ticker.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/tool/run-ticker.tsx)).
- **Permission prompts are inline, not modal, in both open-source products.** Hermes puts a compact approve/deny button strip directly under the pending tool row with `once | session | always | deny` choices ([tool/approval.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/tool/approval.tsx)); OpenHands surfaces confirmation inside the transcript when the agent state is `AWAITING_USER_CONFIRMATION`, with a red risk alert block ([confirmation-mode-enabled.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/confirmation-mode-enabled.tsx)).
- **Terminal fidelity is the sharpest divergence.** OpenHands ships a *read-only* xterm (`disableStdin: true`) ([hooks/use-terminal.ts](https://github.com/OpenHands/OpenHands/blob/main/src/hooks/use-terminal.ts)); Hermes ships a real interactive PTY terminal (xterm 6 + FitAddon + SerializeAddon + Unicode11 + WebLinks + WebGL, scrollback serialized and replayed) ([terminal/instance.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/right-sidebar/terminal/instance.tsx)).
- **Both open-source products use raw WebSocket for the live event stream, which validates Tektos's WebSocket-only constraint.** OpenHands opens WebSocket connections via `useWebSocket` plus a URL builder and preloads history over REST ([use-websocket.ts](https://github.com/OpenHands/OpenHands/blob/main/src/hooks/use-websocket.ts), [utils/websocket-url.ts](https://github.com/OpenHands/OpenHands/blob/main/src/utils/websocket-url.ts)); Hermes speaks JSON-RPC over WebSocket to a gateway with a typed event-name registry ([lib/gateway-events.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/gateway-events.ts)).
- **Session/thread navigation converges on one collapsible left rail plus ⌘K.** OpenHands has a collapsible sidebar with tags, folders, pinned/archived filters and a budget bar ([sidebar.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/sidebar/sidebar.tsx)) and a fuzzy command menu ([command-menu.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/command-menu/command-menu.tsx)); Hermes binds `mod+k`/`mod+p` to a cmdk palette and `mod+.` to a Command Center ([keybinds/actions.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/keybinds/actions.ts)).
- **Perplexity's differentiating GUI ideas are product-level, not implementation-level, and are cheap to copy:** a plan preview with a credit estimate that waits for approval, a *live running credit counter* while the agent works, an Artifacts library reachable from a grid icon in the left sidebar with pinning, expand-to-fullscreen preview and automatic version history, and draw-a-selection-box inline editing of generated documents ([DataCamp hands-on](https://www.datacamp.com/tutorial/perplexity-computer), [Artifacts guide](https://perplexity-artifacts.netlify.app/), [changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)).
- **Design language: Hermes is explicit and enforceable, OpenHands is token-driven, Perplexity is undocumented.** Hermes's rule of thumb is "one source per concern, tokens over literals, flat over boxed", with a 13px conversation font, `--radius: 0.75rem`, hairline strokes instead of borders and a documented z-index ladder ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md), [styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)); OpenHands ships a 13-step cool-grey ramp and three named runtime themes ([themes/color-themes.ts](https://github.com/OpenHands/OpenHands/blob/main/src/themes/color-themes.ts)). No fetched Perplexity source states colors, typography, spacing or dark-mode behavior.
- **Recommended direction for Tektos (detail in §5): keep assistant-ui + Monaco + xterm + D3, adopt Hermes's persistent-pane model and inline approval strip, adopt OpenHands's tabbed workspace and tool-visualizer registry, adopt Perplexity's plan-approval + cost meter + Artifacts library, and collapse the ~50 dashboard panels behind a searchable command surface instead of a wall of tabs.**

## 1. Perplexity Computer

Closed source. There is no repository, so everything below comes from Perplexity's own product/help/changelog pages plus third-party hands-on reviews. Marketing pages are notably thin on interface detail: the product page for Computer describes capability ("creates and executes entire workflows", "capable of running for hours or even months") without naming a single panel, sidebar or control ([Perplexity — Computer product page](https://www.perplexity.ai/products/computer)), and the launch post similarly describes "a real filesystem", "a real browser" and "real tool integrations" without describing any UI for them ([Introducing Perplexity Computer](https://www.perplexity.ai/hub/blog/introducing-perplexity-computer)).

### A. Information architecture & app shell

Computer is a surface *inside* the main Perplexity app rather than a standalone shell. The enterprise help article gives the clearest primary-source flow: from the **Home** page you click the **Computer** icon, then click the **Start a task** field to create a new task, and you click the **Perplexity icon** to return to **Ask Anything** mode and exit Computer ([Computer for Enterprise](https://www.perplexity.ai/help-center/en/articles/13901210-computer-for-enterprise)). That article also names a **Computer sidebar** containing a **Connectors** section ([Computer for Enterprise](https://www.perplexity.ai/help-center/en/articles/13901210-computer-for-enterprise)).

Named destinations that are documented:

- **Computer** entry in the left sidebar, and a tasks route at `perplexity.ai/computer/tasks`, described as "all scheduled tasks in a unified view", plus a **Computer dashboard** and per-task detail pages at `perplexity.ai/computer/tasks/<task-id>` ([Scheduled Tasks in Computer](https://www.perplexity.ai/help-center/en/articles/11521526-perplexity-tasks)).
- A **Computer dashboard** that shows task history alongside **Files**, **Connectors**, **Skills** and **Gallery** panels containing linked output artifacts from completed jobs ([multi-agent orchestration tutorial](https://marketingagent.blog/2026/03/13/tutorial-perplexity-computer-multi-agent-orchestration/)).
- An **Artifacts** tab in the left sidebar, opened via a **grid icon** in the left navigation panel, launched May 2026, holding documents, apps, presentations, websites, images, video and audio, including artifacts shared by teammates ([Artifacts guide](https://perplexity-artifacts.netlify.app/)).
- **History** in the sidebar, where Ask threads and Computer tasks appear together with no separate tabs; on Mac search is a dedicated input field in the sidebar, on Windows a magnifying-glass icon in the top left ([Find Projects, Threads, and Previous Work](https://www.perplexity.ai/help-center/en/articles/19800007-find-projects-threads-and-previous-work)).
- On mobile, Computer is "fully rolled out to the App Store as a new tab within the app" ([changelog 2026-03-13](https://www.perplexity.ai/changelog/what-we-shipped---march-13-2026)); a reviewer describes a **Computer panel** opening from the Perplexity web home page, a **Computer tab** on iOS, and a **Computer task composer** on web ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).
- Enterprise adds a **Computer Configuration tab** in **Settings** for sandbox network-security settings, and Computer **workflows** are reached from the **task bar** in Computer ([changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)).

The Comet browser variant is a different shell: an **Assistant panel** (also called the **Sidecar**) that runs alongside the main browser window so you can browse other pages while Assistant works, with **Computer mode** exposing a **Control browser** skill that can scroll, type, click and open tabs ([Assistant panel help article](https://www.perplexity.ai/help-center/comet/en/articles/11734688-assistant-panel)). The quick-start guide calls it a collapsible sidebar and documents `Alt + A` for the assistant sidebar, `Alt + S` for one-click summarization and `Shift + Alt + V` for Voice Mode ([Comet quick-start guide](https://www.perplexity.ai/comet/resources/articles/comet-quick-start-guide)).

### B. Chat & streaming transcript

Everything is anchored on "a single conversation with shared context" ([Builder.io](https://www.builder.io/blog/perplexity-computer)). Documented transcript-level behavior:

- **Composer controls** (for the Ask surface, which shares the thread UI): Search Modes (**Pro**, **Research**, **Create files and apps**), an AI model selector, a **Sources** control (e.g. Web or Academic), file attachment, and a microphone icon for dictation ([What is a Session?](https://www.perplexity.ai/help-center/en/articles/10354769-what-is-a-thread.html)).
- **Per-answer actions**: **Export** (PDF, Markdown, DOCX), **Rewrite** (regenerate with a different, user-selected model), a **Source** button showing which Model, Search mode and Source mode produced the answer, thumbs-up/down feedback, **Copy**, and a three-dots menu for Sources / Report feedback / delete that portion of the session. Hovering a prompt reveals an edit icon to edit the original query ([What is a Session?](https://www.perplexity.ai/help-center/en/articles/10354769-what-is-a-thread.html)).
- **Markdown-first output**: since 2026-03-27 Computer drafts in "lightweight Markdown" by default and those outputs "appear as clean reports in the thread", downloadable at any time as PDF or DOCX ([changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)).
- **Inline, non-blocking context management**: when a conversation gets long, Computer offers a choice to extend full context for richer detail or summarize and continue at lower cost; the prompt "appears inline" and "does not block the thread" ([changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)). Reviewers confirm context compaction survives multi-day sessions but report there is "no way to branch, clear, or manually summarize context mid-conversation" ([Builder.io](https://www.builder.io/blog/perplexity-computer)).
- **Voice**: Voice Mode is available directly inside Computer on web and lets users describe a project, give feedback mid-task and redirect on the fly without typing ([changelog 2026-03-06](https://www.perplexity.ai/changelog/what-we-shipped---march-6-2026)).
- **Mid-task steering**: reviewers report that users can stop a single sub-agent and type a follow-up instruction mid-task ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).

No fetched source describes message-bubble geometry, streaming token rendering, typing indicators, or transcript keyboard shortcuts. Perplexity does not publish that level of detail.

### C. Agent activity timeline

This is the most instructive part of Perplexity's design for Tektos, and it is documented mainly by hands-on reviewers rather than by Perplexity:

- **Plan preview with cost estimate, gated on approval.** In a real run, the agent produced a written plan listing the eight target tools, the data sources it intended to use, the order of work and "a rough credit estimate", and waited for approval before starting the parallel research phase ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).
- **Activity panel with progress lines.** The reviewer describes an **Activity panel** showing "progress lines with brief notes on which sites were being read" ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).
- **Live cost meter.** A "running credit total" is visible while Computer works, showing exactly how much the task has cost so far in real time ([changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)); the reviewer saw the counter "began ticking up after the plan was approved" and reported a full run of 7 min 59 s costing 225.71 credits ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).
- **Subagent behavior surfaces as interruptions.** Multiple sub-agents ran simultaneously across eight tools and one "paused mid-run to ask whether a company's open-source CLI should count as a separate product" ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)). Architecturally the product decomposes an objective, delegates subtasks to different models, and "checks in with the user only when it genuinely needs input" ([VentureBeat](https://venturebeat.com/technology/perplexity-launches-computer-ai-agent-that-coordinates-19-models-priced-at)).
- **Run states in the task list**: tasks group under **Scheduled**, **Needs attention** and **Completed**; **Needs attention** appears when a background task gets stuck because instructions are unclear or input is required ([Scheduled Tasks in Computer](https://www.perplexity.ai/help-center/en/articles/11521526-perplexity-tasks)). Credit exhaustion pauses a task and the latest agent updates can be read before adding credits ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).
- **Approval and kill switch for the local variant**: for Personal Computer, "every sensitive action requires explicit approval, with a full audit trail and kill switch built in" ([changelog 2026-03-13](https://www.perplexity.ai/changelog/what-we-shipped---march-13-2026)), and a review-oriented write-up says Computer provides "a visible trail of work" that users can inspect, redirect and continue ([Perplexity Computer review](https://perplexityaimagazine.com/perplexity-hub/perplexity-computer-agent-review/)).

### D. Workspace / artifact viewer

Perplexity deliberately does *not* expose the machine. Its artifact story is a preview-and-library story:

- **Side-panel preview with expand.** The user describes what they need in plain language without choosing a file type; Computer determines the format, builds the artifact and "previews it in the side panel", and **Expand** opens the preview full-screen ([Artifacts guide](https://perplexity-artifacts.netlify.app/)).
- **In-place refinement with automatic version history.** Follow-up prompts update the artifact in place; "the previous version is not lost" and "version history is tracked automatically" ([Artifacts guide](https://perplexity-artifacts.netlify.app/)).
- **Export/share**: download in PDF, DOCX, XLSX, PPTX or HTML, export directly to Google Drive if connected, or share a link directly from the thread; artifacts can be **pinned** (pin icon) to stay at the top of the list, and interactive HTML apps can be published to a permanent link ([Artifacts guide](https://perplexity-artifacts.netlify.app/)). DataCamp confirms `*.pplx.app` publishing as an inspectable pre-launch result ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)).
- **Region-scoped inline editing.** For any Computer-generated document, presentation, spreadsheet, web app or PDF, the user draws a **selection box** over part of the asset, types a short instruction, and Computer edits only the selected region in place ([changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)).
- **No code/terminal/preview surface.** A developer review is blunt: work happens in an isolated Linux sandbox (2 vCPU, 8 GB RAM, Python/Node/ffmpeg preinstalled), but "you can't see any of it", there is "no live preview", "no hot reloading", and "no way for you to click around and test a feature as it's being built" — visual verification required pushing to Vercel and waiting 2–3 minutes for a preview build ([Builder.io](https://www.builder.io/blog/perplexity-computer)). The agent can browse its own localhost to check its work, but the user cannot ([Builder.io](https://www.builder.io/blog/perplexity-computer)).

### E. Session management

- Sessions ("threads") are stored indefinitely on a **History** page with a **Search bar**, **Select** for multi-select deletion, **Type** filtering by Search Mode (Pro / Research / Create files and apps), newest-oldest sorting, a control to hide or show sessions created via Comet browser, a dots menu to delete all sessions at once, and a per-session three-dots menu to delete or **Add to a project** ([What is a Session?](https://www.perplexity.ai/help-center/en/articles/10354769-what-is-a-thread.html)).
- **Sharing** is a top-right **Share** button with access levels **Private** and **Anyone with the link**; enterprise admins can disable public session sharing under Organization Settings → Data and privacy, and Roles & Permissions governs sharing sessions and artifacts with groups or external contributors ([What is a Session?](https://www.perplexity.ai/help-center/en/articles/10354769-what-is-a-thread.html)).
- **Projects** organize threads, instructions and cloud files, while a **folder** contains local files on a specific computer; both Ask threads and Computer tasks appear in one sidebar list ([Find Projects, Threads, and Previous Work](https://www.perplexity.ai/help-center/en/articles/19800007-find-projects-threads-and-previous-work)).
- **Scheduling** is conversational rather than form-based: you describe the recurrence in plain language, Computer proposes a schedule plus what the task will do plus a note that each run uses credits, and you approve; supported cadences are hourly, daily at a time, every weekday, weekly, monthly and custom, with a one-hour minimum and no one-time tasks. Each conversation can own up to 15 scheduled tasks, and a **Stop task** button lives in the conversation's right-hand context pane ([Scheduled Tasks in Computer](https://www.perplexity.ai/help-center/en/articles/11521526-perplexity-tasks)). A later update added a homescreen view of every scheduled task, individual pause/cancel, multi-select delete from the task list and a confirmation dialog for single deletes ([changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)).
- Skills and connectors are managed as first-class pages: a **Skills** panel showing installed markdown capability modules with an **Upload a Skill** drop target, and a **Connectors** panel with **Add Connector** → provider → authorization → **Allow** ([orchestration tutorial](https://marketingagent.blog/2026/03/13/tutorial-perplexity-computer-multi-agent-orchestration/)); enterprise connector rows expose **Enable** and an ellipsis → **Disconnect** ([Computer for Enterprise](https://www.perplexity.ai/help-center/en/articles/13901210-computer-for-enterprise)). MCP setup uses a **Simple** tab with a **Server Name** field plus run command, **Save**, and a status such as **Running** in the connectors list ([Local and Remote MCPs](https://www.perplexity.ai/help-center/en/articles/11502712-local-and-remote-mcps-for-perplexity)).

### F. Visual design language

**Not documented in any fetched primary source.** The product page, launch blog, Personal Computer blog, help-center articles and changelogs fetched here state no colors, typography, font sizes, spacing, radii, iconography, motion, density or dark-mode behavior; the product page in particular specifies none of these ([Perplexity — Computer product page](https://www.perplexity.ai/products/computer)) and the Assistant panel article explicitly carries no visual-design detail either ([Assistant panel](https://www.perplexity.ai/help-center/comet/en/articles/11734688-assistant-panel)). The only design-adjacent, source-backed facts are structural (grid icon for Artifacts, pin icon, left navigation panel, right-hand context pane, floating panel next to a text selection in Comet ([changelog 2026-03-13](https://www.perplexity.ai/changelog/what-we-shipped---march-13-2026))). Rather than pad this section with speculation, treat Perplexity's visual language as an unknown that would have to be captured from screenshots, which is outside what a text-fetch research pass can substantiate.

### G. Implementation-level details

**Unavailable.** Perplexity Computer is a closed-source hosted product; there is no repository, no published frontend source, no documented event schema and no published component inventory. The only implementation-adjacent facts found are backend/runtime ones: an isolated Linux cloud sandbox with 2 vCPU and 8 GB RAM and preinstalled Python, Node.js, ffmpeg and Unix tools ([Builder.io](https://www.builder.io/blog/perplexity-computer)), orchestration across 19 models in parallel with automatic routing ([changelog 2026-02-27](https://www.perplexity.ai/changelog/what-we-shipped---february-27-2026)), a default orchestrator model that has shifted over time ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)), and 400+ managed OAuth connectors ([Builder.io](https://www.builder.io/blog/perplexity-computer)). Nothing about its framework, state management, CSS system, transport or event protocol is publicly stated, so no such claims are made here.

## 2. OpenHands

The repository root *is* the frontend: `package.json` declares the package name `@openhands/agent-canvas` at version 1.16.0 with the description "Self-hosted developer control center for coding agents and automations", and lists an `electron/` build alongside the web app ([package.json](https://github.com/OpenHands/OpenHands/blob/main/package.json)).

### A. Information architecture & app shell

Routing is React Router 7 in framework mode, with the route table enumerating: an index home, `/conversations/:conversationId`, a mobile-only `/conversations/:conversationId/panel`, `/launch`, `/customize`, `/skills`, `/plugins`, `/apps`, `/extensions/:name/*`, `/mcp`, a `/settings` branch (llm, agent, agents, condenser, agent-context, verification, app, secrets), an `/automations` branch (git-sync, templates, new, `:id`) and a public `/shared/conversations/:conversationId` route ([src/routes.ts](https://github.com/OpenHands/OpenHands/blob/main/src/routes.ts)).

The conversation shell is a two-pane split: chat on the left and a tabbed workspace on the right, with a draggable divider managed by a `useResizablePanels` hook defaulting to a 50% split, clamped to min 30% / max 80%, persisted to `localStorage` under a `desktop-layout-panel-width` key, with ~300 ms width transitions and an `h-10` chat header; on mobile the workspace collapses and the user is routed to the `/panel` route instead ([conversation-main.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/conversation/conversation-main/conversation-main.tsx), [routes/conversation.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/routes/conversation.tsx)).

Right-pane tabs are a fixed set with overflow handling: Files, Changes/Commits, Planner, Terminal, Browser, Usage and Task List ([conversation-tabs.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/conversation/conversation-tabs/conversation-tabs.tsx)). The user-facing docs name the same surfaces: a **Chat Panel**, a **Changes Tab** showing file changes, an embedded **VS Code** for browsing/modifying and uploading/downloading files, a **Terminal Tab**, an **App Tab** that displays and lets you interact with a running web server, and a **Browser Tab** that is explicitly "non-interactive" ([OpenHands docs — Key Features](https://docs.openhands.dev/openhands/usage/key-features)). A conversation-level drawer aggregates git, MCP, secrets, skills, automations and diffs ([conversation-main.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/conversation/conversation-main/conversation-main.tsx)).

Settings are a dedicated page tree covering LLM provider/model selection, search engine, MCP servers, GitHub/GitLab/Bitbucket connections, application preferences (language, notifications) and custom secrets, with a first-launch settings popup using labeled fields `LLM Provider`, `LLM Model`, `see advanced settings`, `Advanced`, `Custom Model`, `API Key` and `Save Changes`; the GUI server itself is served at `http://localhost:3000` ([OpenHands docs — GUI mode](https://docs.openhands.dev/openhands/usage/run-openhands/gui-mode)).

### B. Chat & streaming transcript

The transcript is a typed event stream, not a message array. `event-message.tsx` dispatches on event kind, handling goal-state changes, agent errors, hook executions, ACP sub-agent tool calls, streaming deltas, finish actions and think actions, and falls back to a generic wrapper that pairs observations to their originating actions by `action_id` ([event-message.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/event-message.tsx)).

- **Bubbles.** A message renders as an `<article>` with `rounded-xl`; user messages get `bg-tertiary self-end px-4 py-2.5` while agent messages are full-width and transparent, with no avatars and hover-revealed action buttons; planning-agent messages get a distinguishing border color ([chat-message.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/chat-message.tsx), [user-assistant-event-message.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/event-message-components/user-assistant-event-message.tsx)).
- **Streaming.** `StreamingDeltaEvent` payloads are rendered incrementally and inline `<think>` content is split out of the visible answer ([event-message.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/event-message.tsx)); a separate typing indicator component exists ([typing-indicator.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/typing-indicator.tsx)).
- **Thinking display.** Reasoning is wrapped in a collapsible thinking block rather than shown inline by default ([collapsible-thinking.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/event-message-components/collapsible-thinking.tsx)).
- **Inline tool calls.** Tool cards are collapsed by default with a chevron, an icon, a trailing title slot, a success indicator and a hover tooltip carrying the timestamp; a dispatcher maps event kinds to specialized visualizers over shared primitives (code block, diff view, file-path chip, key-value grid, markdown file preview, output pane) ([tool-visualizers/dispatcher.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/tool-visualizers/dispatcher.tsx), [generic-event-message.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/generic-event-message.tsx)). The bash visualizer shows the command, a HIGH/MEDIUM risk warning where applicable, and an exit-code badge ([bash.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/tool-visualizers/bash/bash.tsx)).
- **Diffs in transcript** use a hand-rolled LCS diff primitive with three lines of context and a 300-row cap ([diff-view.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/tool-visualizers/primitives/diff-view.tsx)).
- **Markdown** is rendered with `react-markdown` plus `remark-gfm`/`remark-breaks` and `rehype-raw`/`rehype-sanitize` ([package.json](https://github.com/OpenHands/OpenHands/blob/main/package.json)) behind a hardened sanitize schema that strips `style` attributes and `data:` URLs ([markdown-renderer.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/markdown/markdown-renderer.tsx)).

Drafts are debounced and persisted to localStorage ([use-draft-persistence.ts](https://github.com/OpenHands/OpenHands/blob/main/src/hooks/chat/use-draft-persistence.ts)).
- **Shortcuts.** `⌘K` opens a fuzzy command menu grouped into navigation, settings and actions ([command-menu.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/command-menu/command-menu.tsx), [command-menu-items.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/command-menu/command-menu-items.tsx)); the chat surface advertises `⌘↩` for Build/Continue and a shift-modified shortcut for rejecting, wired through the chat input event hook ([use-chat-input-events.ts](https://github.com/OpenHands/OpenHands/blob/main/src/hooks/chat/use-chat-input-events.ts), [conversation-tabs.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/conversation/conversation-tabs/conversation-tabs.tsx)).

There is no evidence in the fetched source of branch/fork of a conversation from the transcript; regeneration and editing are not exposed the way Perplexity exposes Rewrite.

### C. Agent activity timeline

OpenHands does not have a separate timeline surface; activity is expressed three ways.

1. **A live-activity pill in the chat column.** A `rounded-full px-3 py-1.5 text-xs` chip with a pulsing dot, `aria-live="polite"` and `data-testid="live-activity-chip"`, whose label is computed by a `deriveLiveActivity()` helper from the most recent events ([chat-interface.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/chat-interface.tsx)).
2. **An agent-status control** rendering an 11px status label next to a 24px morphing action button that fades out about a second after settling, backed by an `useAgentNotification` behavior that flashes the tab title and plays a sound; the state machine covers init, loading, running, paused, stopped, error, rate-limited and awaiting-user-confirmation ([agent-status.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/controls/agent-status.tsx)).
3. **Plan and task-list surfaces.** A plan preview component renders proposed plans in the transcript ([plan-preview.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/plan-preview.tsx)), and task tracking renders a card with a compact header and 12px item titles, with a dedicated tab in the right pane ([task-list-section.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/task-tracking/task-list-section.tsx), [task-item.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/task-tracking/task-item.tsx)).

Sub-agents appear as ACP tool-call events inside the transcript rather than as a roster ([event-message.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/conversation-events/chat/event-message.tsx)). Permission prompts are inline: when the agent reaches `AWAITING_USER_CONFIRMATION`, a confirmation component renders in flow with a red risk-alert block ([confirmation-mode-enabled.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/confirmation-mode-enabled.tsx)). ## 3. Hermes Agent

The desktop app is `apps/desktop`, package name `hermes`, productName **Hermes**, version 0.17.2, described as the "Native desktop shell for Hermes Agent", packaged by electron-builder with appId `com.nousresearch.hermes`, a `hermes:` protocol scheme, and dmg/zip/nsis/msi/AppImage/deb/rpm targets ([apps/desktop/package.json](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/package.json)).

### A. Information architecture & app shell

`DESIGN.md` states the IA rules outright: "Chat is the home surface"; durable pages are Chat, Skills, Messaging and Artifacts; "route overlays are short tasks" — Settings, Command Center, Cron, Profiles, Agents and Starmap render as overlay cards that return you to the previous route; "panes are working context" (preview, files, review, terminal persist); "one action, one home"; and Projects own the workspace cwd ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).

The route table encodes this: sessions live at the root prefix so a session URL is `/<sessionId>` and `/` is a new chat, with reserved paths `/settings`, `/command-center`, `/session-import`, `/skills`, `/messaging`, `/webhooks`, `/artifacts`, `/cron`, `/profiles`, `/agents` and `/starmap`, of which session-import, agents, command-center, cron, profiles, settings, starmap and webhooks are declared overlay views; plugins can contribute full pages and sidebar nav entries through a registry ([app/routes.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/routes.ts)).

The shell is a custom titlebar plus optional statusbar plus a left session sidebar plus a right sidebar `<aside>` whose border side flips when panes are flipped, with pane sizing persisted per pane ([shell/titlebar-controls.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/shell/titlebar-controls.tsx), [shell/statusbar-controls.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/shell/statusbar-controls.tsx), [right-sidebar/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/right-sidebar/index.tsx), [store/panes.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/store/panes.ts)). Beyond side panes there is a genuine tiling pane tree with a grid model, presets, drag sessions, floating panes, a tab strip and a zones engine ([components/pane-shell/index.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/pane-shell/index.ts)). Window translucency defaults to "29% Tint, Sidebar only" ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)). The user docs add pop-out single-chat windows whose live output streams to every window, plus a chrome-free always-on-top **HUD mode** ([website/docs/user-guide/desktop.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/desktop.md)).

### B. Chat & streaming transcript

The transcript and composer are built on `@assistant-ui/react`, and `DESIGN.md` forbids forking a second markdown, message, tool-call or approval renderer: extensions must land in `src/components/assistant-ui` and `src/app/chat/composer` ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).

- **Message components** are split into assistant-message, user-message, a user edit composer, message-parts, reactions, status, system-message, a changed-files card, agent-delivery and turn-activity ([thread/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/index.tsx), [thread/assistant-message.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/assistant-message.tsx), [thread/user-message.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/user-message.tsx), [thread/message-parts.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/message-parts.tsx)).
- **Remount discipline**: `Thread` is memoized with a stable component map and callbacks-ref pattern specifically so switching sessions does not remount the outgoing transcript ([thread/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/index.tsx)).
- **Markdown/streaming** uses assistant-ui's streamdown integration (`@assistant-ui/react-streamdown`, `streamdown` with code and math plugins), with shiki highlighting, KaTeX math, mermaid diagrams and an ANSI text renderer for tool output ([apps/desktop/package.json](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/package.json)).
- **Inline widgets** — embeds for YouTube, Spotify, X, TikTok, Instagram, Pinterest, maps, Vimeo, mermaid, SVG and generic frames behind a consent gate — all wear a single `WIDGET_SHELL_CLASS`, with actions placed *outside* the panel ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Editing/rewind**: a `ThreadEditContext` drives the user edit composer, and restore/rewind operations go through the single `ConfirmDialog` primitive ([thread/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/index.tsx), [DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Prompt rail (signature move)**: `ThreadTimeline` is a right-edge rail with one tick per user turn, appearing only at four or more turns, with a hover popover of prompt previews (`w-80`, max height 22rem) and a click that jumps with a fixed ~170 ms `easeOutCubic` scroll animation rather than native smooth scrolling, plus a selection haptic and four laziness gates so an inactive pane renders nothing ([thread/timeline.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/timeline.tsx)).
- **Composer**: a rich contentEditable editor with attachments, a completion drawer, slash/at/emoji completions, directive chips, a model pill, a queue panel, voice input with barge-in, pop-out, undo history and suggestion pills, sized by `--composer-control-size: 1.5rem` and `--composer-input-min-height: 1.625rem` with a computed `--composer-measured-height` ([chat/composer/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/chat/composer/index.tsx), [chat/composer/controls.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/chat/composer/controls.tsx), [styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)).
- **Composer keys**: Enter sends, Shift+Enter newlines, `mod+Enter` queues, Esc cancels, up/down walks history, `@` mentions, `/` opens slash commands, `?` opens help, `mod+l` focuses the composer or sends the selection to it ([keybinds/actions.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/keybinds/actions.ts)). Stop/Esc pauses the run and expands the editable queue, and `Cmd/Ctrl+F` searches the transcript in place ([website/docs/user-guide/desktop.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/desktop.md)).

### F. Visual design language

- **Stated rule of thumb**: "one source per concern, tokens over literals, flat over boxed", with principles of flat-not-boxed, borderless elevation (a `shadow-nous` plus a `--stroke-nous` hairline), one primitive per concern, style living in the primitive, "intent before automation" (never auto-open panes or steal focus) and immediate feedback with visible rollback ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Color/text tokens**: `--ui-stroke-primary…quaternary` (tertiary is the default hairline), `--ui-text-primary/-secondary/-tertiary` computed as `color-mix()` tiers at roughly 94/74/54/36% of a base, `--conversation-scaffold-text` at 64% and `-meta` at 44%, plus `--stroke-nous: color-mix(in srgb, currentColor 3%, transparent)` ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md), [styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)).
- **Density**: `--radius: 0.75rem` with a `--radius-scalar` of 0.2, conversation text 0.8125rem (13px), tool text 0.6875rem (11px), caption 0.75rem, line height 1.125rem, turn gap 0.375rem (0.1875rem in compact), composer control 1.5rem, composer input min 1.625rem and max 9.375rem, and a `compact` custom variant that triggers at `max-height: 768px` ([styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)).
- **Component discipline**: a single `Button` with variants default/destructive/secondary/outline/ghost/link/text/textStrong and sizes default/xs/sm/lg/inline/micro/icon, where SVGs inherit `size-3.5`, text buttons are square and only icon buttons get a 4px radius; one `Badge`; shared `controlVariants`; a borderless `SearchField` that underlines on focus; `SegmentedControl`; `Switch`; and a `Tip` tooltip with a 200 ms first-open delay and 300 ms warm window that must never fall back to a native `title=` attribute (enforced by a test) ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Feedback primitives**: a `Loader` built from animated math/ascii curves including a "lemniscate-bloom", `ErrorState`/`ErrorIcon`, `LogView`, `EmptyState`/`PanelEmpty`, and a single `ConfirmDialog` as the only sanctioned way to ask "are you sure" (never `window.confirm`), mounted through one `ConfirmHost` ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Iconography**: Tabler icons by default through a central `icons.ts` with an `iconSize` helper, VS Code Codicons for editor/tool/status contexts, and a `BrandMark` that is the one sanctioned visual literal ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md), [apps/desktop/package.json](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/package.json)).
- **Motion**: functional transitions around 100 ms, `prefers-reduced-motion` respected, choreographed exits, the maxim "motion follows state; it never delays state", and a prohibition on `transition-all` in hot interactions ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)).
- **Z-index ladder** documented as tokens: modal backdrop 120, modal 130, modal popover 140, over-modal 200/210, switcher backdrop 219, switcher 220, connecting 1200, onboarding 1300/1310, setup 1400, crash 1500 ([styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)).
- **Themes**: eleven presets — github, nous, nous-alt, catppuccin, everforest, solarized, midnight, ember, mono, cyberpunk, slate — with typography defaulting to system sans/mono and per-theme font overrides, plus VS Code Marketplace theme import, retinting, skins and user themes ([themes/presets.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/themes/presets.ts), [website/docs/user-guide/desktop.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/desktop.md)).
- **Signature moments**: the right-edge prompt rail with its fixed-duration jump scroll and haptic ([thread/timeline.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/timeline.tsx)), the sliding one-line tool ticker ([tool/run-ticker.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/tool/run-ticker.tsx)), and the HUD mode that reduces the whole app to a floating bar ([website/docs/user-guide/desktop.md](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/desktop.md)).

## 5. Synthesis recommendations for Tektos

### A. Information architecture & app shell

**Copy from Hermes:** make chat the home surface and demote the ~50 panels from peers-of-chat to overlays and panes. Hermes's split of "durable pages" vs "route overlays are short tasks" vs "panes are working context" ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md)) maps almost one-to-one onto Tektos: Chat and a Dashboard-of-record stay durable; Config, Keys, Hooks, Scheduling, Settings, Evaluation, SchemaEvolution become overlay routes; Telemetry, Logs, Memory, RepoMap, Planner become panes. **Copy from OpenHands:** the resizable chat/workspace split with a persisted width and a mobile fallback route ([conversation-main.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/conversation/conversation-main/conversation-main.tsx)). **Invent anew:** the ChatPage/`/dashboard` split should be replaced by one shell where the dashboard is a *destination* rather than a separate application, and the ~50 panels get a registry with metadata (category, subsystem, requires-connection) so the palette and pane tree can enumerate them instead of a hand-maintained tab bar. Reuse Next.js app router for the overlay pattern (parallel/intercepted routes give you Hermes's "overlay returns to previous route" behavior natively).

### B. Chat & streaming transcript

**Copy from Hermes:** stay on `@assistant-ui/react` 0.14 and adopt its discipline — one markdown renderer, one message renderer, one tool-call renderer, one approval renderer, with all extensions living under a single `components/assistant-ui` tree, plus the memoized `Thread` with a stable component map so switching sessions never remounts the outgoing transcript ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md), [thread/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/index.tsx)). Adopt the right-edge prompt rail with a 4-turn threshold and fixed-duration jump scroll ([thread/timeline.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/thread/timeline.tsx)) — it is the cheapest high-value navigation win for long autonomous runs. **Copy from OpenHands:** the tool-visualizer *registry* keyed by event kind over shared primitives (code block, diff, file chip, key-value grid, output pane), and the hardened markdown sanitize schema ([dispatcher.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/tool-visualizers/dispatcher.tsx), [markdown-renderer.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/markdown/markdown-renderer.tsx)) — Tektos's `tool.started`/`tool.delta`/`tool.completed` triple maps directly onto it. **Copy from Perplexity:** per-answer export to Markdown/PDF/DOCX and a "which model/mode produced this" provenance popover ([help center](https://www.perplexity.ai/help-center/en/articles/10354769-what-is-a-thread.html)), which pairs naturally with Tektos's `model_switched` event. **Invent anew:** Tektos-specific transcript decorations for `self_improvement.tick` and `resource.warning` — treat them as scaffold rows in the Hermes sense (dim, aria-live, non-blocking), not as chat messages.

### C. Agent activity timeline

**Copy from Hermes:** the composer status stack is the single best structural idea here — status row, coding row, preview row, session control (goal/heartbeat/loop), subagent section, and an expandable Tasks panel, all stacked above the composer where the user's eyes already are ([status-stack/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/chat/composer/status-stack/index.tsx), [subagent-section.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/chat/composer/status-stack/subagent-section.tsx)). Also copy the inline approval strip with once/session/always/deny plus a floating fallback anchored to `--composer-measured-height` ([tool/approval.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/components/assistant-ui/tool/approval.tsx)) — this is the right home for Tektos's `tool.permission.required`, and it beats a modal for an agent that asks often. **Copy from OpenHands:** `deriveLiveActivity()` as a pure function from recent events to one short phrase, rendered in a pulsing `aria-live` chip, and the notification behavior that flashes the tab and plays a sound when a long run finishes ([chat-interface.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/chat-interface.tsx), [agent-status.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/controls/agent-status.tsx)). **Copy from Perplexity:** the plan-preview-with-estimate that blocks on approval and the live running cost counter ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer), [changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)); for a local-model system the equivalent meter is tokens, VRAM and wall-clock rather than credits, which Tektos already has data for via Metabolism/Thermal/Inference. **Invent anew:** a run-state ribbon that fuses `session.interrupted`, `session.failed`, `resource.warning` and Thermal/Immune state into one honest health indicator, since no reference product has to reconcile biological-subsystem signals with agent run state.

### D. Workspace / artifact viewer

**Copy from Hermes:** persistent panes with per-pane size overrides in localStorage, the "never auto-open a pane or steal focus" rule, a real interactive terminal (xterm + PTY, serialized scrollback replayed on relaunch, every tab stays mounted with visibility toggling), and the git review pane with **Last turn** diff scoping, which is exactly the review surface an autonomous coding agent needs ([store/panes.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/store/panes.ts), [DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md), [terminal/instance.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/right-sidebar/terminal/instance.tsx), [review/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/right-sidebar/review/index.tsx)). **Copy from OpenHands:** two-tier diffing — a cheap capped in-transcript diff for glanceable changes and Monaco's DiffEditor for the real review ([diff-view.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/chat/tool-visualizers/primitives/diff-view.tsx), [file-diff-viewer.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/diff-viewer/file-diff-viewer.tsx)) — and an interactive App/preview tab for a running dev server, which both OpenHands has and Perplexity conspicuously lacks ([docs](https://docs.openhands.dev/openhands/usage/key-features), [Builder.io](https://www.builder.io/blog/perplexity-computer)). **Copy from Perplexity:** the Artifacts library with pinning, expand-to-fullscreen preview, automatic version history and download/share, plus selection-box region editing for generated documents ([Artifacts guide](https://perplexity-artifacts.netlify.app/), [changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)). **Reuse vs replace:** keep Monaco (it is already in Tektos, it beats CodeMirror for diffing, and OpenHands proves the DiffEditor path); keep `@xterm/xterm` 6 but upgrade the Hermes way — add fit/serialize/unicode11/web-links/webgl addons and a real PTY channel over the existing WebSocket rather than a read-only log.

### E. Session management

**Copy from Hermes:** rebindable keybinds that persist only diffs with conflict detection, a cmdk palette that ranks in React and folds navigation, projects, models, themes and system actions into one surface, and the session-identity discipline (durable vs runtime vs lineage-root ids; every persisted key declares its scope) ([store/keybinds.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/store/keybinds.ts), [command-palette/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/command-palette/index.tsx), [apps/desktop/AGENTS.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/AGENTS.md)). **Copy from OpenHands:** sidebar affordances that scale — tags, folders, pinned/archived, a budget bar, and a public share route for a single conversation ([sidebar.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/sidebar/sidebar.tsx), [src/routes.ts](https://github.com/OpenHands/OpenHands/blob/main/src/routes.ts)). **Copy from Perplexity:** conversational scheduling where the agent proposes the cadence and states the cost before you approve, plus per-task pause/cancel, multi-select delete and a delete confirmation ([help center](https://www.perplexity.ai/help-center/en/articles/11521526-perplexity-tasks), [changelog 2026-03-27](https://www.perplexity.ai/changelog/what-we-shipped--march-27-2026)) — a better front end for Tektos's existing Scheduling panel than a cron form. **Invent anew:** session lineage as a first-class concept for a self-improving agent — Tektos's `self_improvement.tick` implies runs that spawn successor runs, and neither reference product models an ancestry graph of sessions.

### F. Visual design language

**Copy from Hermes, almost verbatim:** the rule of thumb "one source per concern, tokens over literals, flat over boxed"; borderless elevation via a hairline `color-mix` stroke plus one shadow token; one Button, one Badge, one SearchField, one Tip, one ConfirmDialog with a single host; a documented z-index ladder as CSS variables; ~100ms functional motion with `prefers-reduced-motion` and no `transition-all` on hot paths; and enforcement by test (the no-native-`title` test is the model to imitate) ([DESIGN.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/DESIGN.md), [styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)). Adopt Hermes's density numbers as the starting scale for an information-dense agent console: 13px conversation text, 11px tool text, 12px captions, 18px line height, 6px turn gap, 0.75rem radius, plus a `compact` variant at ≤768px viewport height ([styles.css](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/styles.css)). **Copy from OpenHands:** a numeric neutral ramp (13 steps) as the palette spine with a small set of named runtime themes rather than ad-hoc colors ([color-themes.ts](https://github.com/OpenHands/OpenHands/blob/main/src/themes/color-themes.ts)). **From Perplexity, copy nothing visual** — its visual language is not documented in any fetchable source, so any imitation would be guesswork. **Invent anew:** the BiologicalGraph and the self-repair/immune/nervous surfaces need a visual vocabulary that does not exist in any of the three references. Keep D3 7 + d3-force-3d for that graph (Hermes's Star Map validates force-directed memory graphs as a real product surface, and it uses `d3-force` too ([app/starmap/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/starmap/index.tsx), [apps/desktop/package.json](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/package.json))), but hold it to the same token system as everything else: dim tiers for scaffold, one accent, hairlines, ~100ms transitions.

### Reuse vs replace, at a glance

- **Reuse `@assistant-ui/react` 0.14** — Hermes runs the same major in production with a JSON-RPC-over-WebSocket backend and an incremental external-store runtime, which is the closest possible precedent for Tektos's 15-event envelope protocol ([apps/desktop/package.json](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/package.json), [lib/chat-runtime.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/chat-runtime.ts)).
- **Reuse Monaco** for code and diffs; do not swap to CodeMirror. OpenHands demonstrates Monaco's DiffEditor with a custom theme in exactly this context ([file-diff-viewer.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/diff-viewer/file-diff-viewer.tsx)).
- **Reuse xterm 6, but replace the read-only pattern** with Hermes's interactive PTY + addon set + scrollback serialization ([terminal/instance.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/right-sidebar/terminal/instance.tsx)).
- **Reuse D3 for the BiologicalGraph**, precedent-backed by Hermes's Star Map ([app/starmap/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/starmap/index.tsx)).
- **Replace the ~50-panel flat surface** with a registry + palette + pane tree; both reference products cap visible tabs at roughly seven and push everything else into a searchable command surface ([conversation-tabs.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/components/features/conversation/conversation-tabs/conversation-tabs.tsx), [command-palette/index.tsx](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/app/command-palette/index.tsx)).
- **Keep WebSocket-only.** Neither reference product uses SSE for its live agent stream; OpenHands uses raw WebSocket with REST only for history backfill ([use-websocket.ts](https://github.com/OpenHands/OpenHands/blob/main/src/hooks/use-websocket.ts), [conversation-websocket-context.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/contexts/conversation-websocket-context.tsx)), and Hermes uses JSON-RPC over WebSocket ([lib/gateway-events.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/gateway-events.ts)).
- **Add two protocol fields Tektos's references lack or handle carefully:** a monotonic sequence number and a protocol version. OpenHands's `BaseEvent` carries only a ULID id, ISO timestamp and source ([core/index.ts](https://github.com/OpenHands/OpenHands/blob/main/src/types/agent-server/core/index.ts)), while Hermes has to compensate for unscoped events by pinning them to whichever session received `message.start` ([lib/gateway-events.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/gateway-events.ts)) — a per-session sequence number would remove that whole class of bug.

## 6. Open questions

1. **Perplexity's visual language is unresolved.** No fetched Perplexity source states color, typography, spacing, radius, motion or dark-mode behavior ([product page](https://www.perplexity.ai/products/computer), [Assistant panel](https://www.perplexity.ai/help-center/comet/en/articles/11734688-assistant-panel)). Capturing it would require screenshots or live inspection, which this text-fetch pass cannot substantiate.
2. **Perplexity's activity panel is single-sourced.** The **Activity panel** with per-site progress lines rests on one hands-on review ([DataCamp](https://www.datacamp.com/tutorial/perplexity-computer)); it is not confirmed by a Perplexity-published page, so its exact structure should be verified before copying details.
3. **Does OpenHands support conversation forking or message regeneration?** Nothing in the fetched frontend source shows it, but absence in ~40 sampled files is not proof; the remaining `src/components/features/chat` tree was not exhaustively read.
4. **OpenHands' two-socket model (main + planning) needs confirmation of its division of labor** before deciding whether Tektos should ever open a second socket ([conversation-websocket-context.tsx](https://github.com/OpenHands/OpenHands/blob/main/src/contexts/conversation-websocket-context.tsx)).
5. **Hermes's assistant-ui runtime adapter is the highest-value unread file.** `incremental-external-store-runtime` is the exact bridge Tektos needs between a WebSocket envelope stream and assistant-ui 0.14; it should be read line by line during implementation planning rather than summarized ([lib/chat-runtime.ts](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/src/lib/chat-runtime.ts)).
6. **Electron-specific assumptions in Hermes need translation.** Hermes's three-authority rule assumes an Electron main process owning the machine ([apps/desktop/AGENTS.md](https://github.com/NousResearch/hermes-agent/blob/main/apps/desktop/AGENTS.md)); Tektos is a Next.js web app, so PTY, file-tree and worktree features need a server-side owner defined before those patterns are copied.
7. **How should ~50 panels be grouped?** No reference product carries this many surfaces, so the categorization (subsystem vs lifecycle vs datastore vs observability) is a Tektos-original design decision with no external precedent to copy.
8. **Cost/resource metering equivalence.** Perplexity's credit counter has an obvious analogue in tokens/VRAM/wall-clock for local models, but which single number belongs in the status ribbon is unresolved and should be decided against the Metabolism/Thermal/Inference panel data model.
